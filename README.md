# E1-2 Python 퀴즈 게임

## 프로젝트 개요

Python 기본 문법과 클래스, JSON 파일 저장을 연습하기 위한 콘솔 퀴즈 게임입니다.
코드는 설명하기 쉽도록 `main.py` 하나에 `Quiz`와 `QuizGame` 두 클래스만 사용했습니다.

## 퀴즈 주제와 선정 이유

주제는 Python 기초입니다.
프로그램을 만들면서 사용한 `list`, `dict`, 조건문, 함수, 예외 처리를 문제로 다시 복습하기 위해 선택했습니다.
기본 문제는 5개입니다.

## 실행 환경

- Python 3.10 이상
- 외부 라이브러리 없음
- Windows, macOS, Linux에서 실행 가능

## 실행 방법

```bash
git clone https://github.com/juhyulee/E1-2.git
cd E1-2
python main.py
```

macOS:

```bash
python3 main.py
```

## 메뉴와 기능

```text
=== Python 퀴즈 게임 ===
1. 퀴즈 풀기
2. 퀴즈 추가
3. 퀴즈 목록
4. 점수 확인
5. 종료
```

- 퀴즈 풀기: 저장된 문제를 순서대로 풀고 100점 기준으로 점수를 계산합니다.
- 퀴즈 추가: 문제, 선택지 4개, 정답 번호를 입력하고 즉시 저장합니다.
- 퀴즈 목록: 등록된 문제 제목을 출력합니다.
- 점수 확인: 지금까지의 최고 점수를 출력합니다.
- 종료: 현재 퀴즈와 최고 점수를 저장합니다.

빈 입력, 문자가 들어간 숫자 입력, 범위를 벗어난 숫자는 다시 입력받습니다.
`Ctrl+C` 또는 입력 종료가 발생하면 가능한 데이터를 저장한 뒤 안전하게 종료합니다.

## 클래스 설명

### Quiz

퀴즈 한 문제를 나타냅니다.

- 속성: `question`, `choices`, `answer`
- `show()`: 문제와 선택지 출력
- `is_correct()`: 사용자의 정답 확인
- `to_dict()`: JSON 저장용 딕셔너리 변환

### QuizGame

게임 전체를 관리합니다.

- 퀴즈 목록과 최고 점수 보관
- 메뉴 실행
- 퀴즈 풀기·추가·목록·점수 기능
- `state.json` 저장과 불러오기
- 숫자와 빈 입력 검증

## state.json

위치: 프로젝트 루트의 `state.json`

```json
{
  "quizzes": [
    {
      "question": "Python에서 여러 값을 순서대로 저장하는 자료형은?",
      "choices": ["int", "list", "bool", "str"],
      "answer": 2
    }
  ],
  "best_score": null
}
```

- `quizzes`: 문제 목록
- `question`: 문제 내용
- `choices`: 선택지 4개
- `answer`: 정답 번호 1~4
- `best_score`: 최고 점수. 아직 풀지 않았다면 `null`

파일은 UTF-8로 읽고 씁니다.
파일이 없거나 손상되면 기본 퀴즈 5개로 시작합니다.

## Python 개념 설명

### 변수와 자료형

- 변수: 값을 이름으로 저장해 다시 사용하기 위한 공간
- `int`: 정답 번호와 점수 같은 정수
- `str`: 문제와 선택지 같은 문자열
- `bool`: 정답인지 아닌지 나타내는 참·거짓
- `list`: 여러 퀴즈와 선택지를 순서대로 저장
- `dict`: JSON에 저장할 키와 값의 묶음

### 조건문과 반복문

- `if/elif/else`: 메뉴 번호나 정답 여부에 따라 다른 코드를 실행합니다.
- `for`: 퀴즈와 선택지처럼 개수가 정해진 목록을 순회합니다.
- `while`: 메뉴와 잘못된 입력을 계속 반복합니다.

### 클래스와 객체

- 클래스: 관련 데이터와 기능을 묶은 설계도
- 객체: 클래스로 실제 생성한 값
- `__init__`: 객체를 만들 때 속성을 초기화하는 메서드
- `self`: 현재 객체 자신

함수는 입력을 받아 한 가지 계산을 하고 끝나는 작업처럼, 오래 유지할 상태가 없을 때 사용합니다.
클래스는 여러 메서드가 같은 상태를 계속 공유하거나 변경해야 할 때 사용합니다.
이 프로젝트에서 `Quiz`는 문제·선택지·정답을 함께 보관하고, `QuizGame`은 메뉴가 반복되는 동안 퀴즈 목록과 최고 점수를 유지해야 하므로 클래스로 만들었습니다.

### JSON과 예외 처리

JSON은 `dict`와 `list` 형태의 데이터를 텍스트 파일로 저장하기 좋습니다.
작은 단일 사용자 프로그램에서는 별도 데이터베이스 설치가 없고 표준 라이브러리만으로 처리할 수 있어 가볍습니다.
다만 필드 이름을 반복해서 저장하므로 바이너리 형식보다 용량이 크고, 읽을 때 전체 텍스트를 파싱하는 비용이 있습니다.
따라서 현재처럼 퀴즈가 적을 때는 단순한 JSON이 적합하지만 데이터가 커지면 데이터베이스가 더 효율적입니다.
`try/except`를 사용해 파일 없음, JSON 손상, 입력 중단 오류를 처리합니다.

## Git 작업 조건

기존 저장소에는 10개 이상의 기능 단위 커밋과 `feature/quiz-play` 브랜치 병합 기록이 있습니다.

### 커밋 메시지 규칙

Conventional Commits를 간단히 적용해 `종류: 변경 요약` 형식으로 작성합니다.

- 종류: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`
- 제목은 무엇을 바꿨는지 알 수 있게 작성하고 50자 이내를 권장합니다.
- 설명이 더 필요하면 빈 줄 뒤 본문에 변경 이유를 쓰고 한 줄은 72자 이내를 권장합니다.
- `수정`, `업데이트`처럼 작업 내용을 알 수 없는 메시지는 사용하지 않습니다.

```text
feat: 퀴즈 추가 기능 구현
fix: 손상된 JSON 복구 처리
docs: 실행 방법과 백업 절차 추가
```

### 브랜치와 병합

브랜치는 완성되지 않은 기능을 `main`과 격리해, 작업 중에도 `main`을 실행 가능한 상태로 유지하기 위해 사용합니다.
예를 들어 `feature/quiz-play`에서 퀴즈 풀기를 구현하고 테스트한 다음 `main`에 병합했습니다.
병합은 두 브랜치의 변경 이력을 하나로 통합하는 작업입니다.
두 브랜치가 같은 줄을 다르게 수정했다면 충돌이 발생하며, 올바른 내용을 직접 선택한 뒤 다시 테스트하고 커밋해야 합니다.

```bash
git log --oneline --graph --all
```

`clone → 수정 → commit → push → 기존 폴더에서 pull` 실습 기록:

[Git 워크플로 로그](evidence/logs/git-workflow.txt)

| 명령 | 역할 |
|---|---|
| `git init` | 로컬 저장소 생성 |
| `git add` | 커밋할 변경 선택 |
| `git commit` | 변경 이력 저장 |
| `git push` | 로컬 커밋을 GitHub에 전송 |
| `git pull` | 원격 변경을 가져오기 |
| `git checkout` | 브랜치 생성 또는 전환 |
| `git clone` | 원격 저장소 복제 |

Git은 로컬 버전 관리 도구이고 GitHub는 원격 저장소와 협업 서비스입니다.

## 퀴즈 1000개로 확장할 때

현재 구조는 시작할 때 JSON 전체를 메모리에 올리고 저장할 때 파일 전체를 다시 씁니다.
퀴즈 수를 `n`이라고 하면 불러오기·저장은 `O(n)`, 제목이나 주제를 순서대로 찾는 검색도 `O(n)`입니다.
1000개 정도는 실행할 수 있지만 파일 크기와 메모리 사용량이 늘고, 목록 전체 출력·검색·저장이 느려지며 저장 중 중단되면 파일 전체가 손상될 위험이 있습니다.

먼저 퀴즈 ID나 주제를 키로 하는 `dict` 인덱스를 메모리에 만들고, 목록은 페이지 단위로 출력할 수 있습니다.
데이터가 계속 늘어나면 JSON 대신 SQLite로 옮겨 ID·주제 열에 인덱스를 만들면 필요한 행만 검색하고 수정할 수 있습니다.
여러 사용자가 동시에 사용한다면 트랜잭션과 동시 접속을 지원하는 서버형 데이터베이스를 고려합니다.

## 백업과 복구

- 사용 중에는 하루 한 번, 큰 변경 전에는 즉시 `state.json`을 백업합니다.
- 백업은 저장소 밖의 `../E1-2-backups/`에 두고 최근 일간 7개와 주간 4개를 보관합니다.
- 중요한 백업 한 벌은 외장 드라이브나 클라우드처럼 다른 장치에도 보관합니다.

macOS/Linux 백업 예시:

```bash
mkdir -p ../E1-2-backups
cp state.json "../E1-2-backups/state-$(date +%Y%m%d-%H%M%S).json"
```

Windows PowerShell 백업 예시:

```powershell
New-Item -ItemType Directory -Force ..\E1-2-backups
Copy-Item state.json "..\E1-2-backups\state-$(Get-Date -Format yyyyMMdd-HHmmss).json"
```

손상이 의심되면 프로그램을 종료해 덮어쓰기를 막고, 손상된 파일을 별도 이름으로 보관합니다.
가장 최근 백업부터 `python3 -m json.tool <백업파일>`로 JSON 형식을 확인한 뒤, 정상 백업을 `state.json`으로 복사합니다.
Windows에서는 `python -m json.tool <백업파일>`을 사용합니다.
복구 후 프로그램을 실행해 퀴즈 개수와 최고 점수가 맞는지 확인합니다.

## 평가 때 설명할 핵심

1. `Quiz`는 문제 하나, `QuizGame`은 게임 전체를 담당합니다.
2. 메뉴는 `while`, 문제와 선택지는 `for`로 반복합니다.
3. `if/elif/else`로 메뉴 기능과 정답을 구분합니다.
4. 퀴즈와 최고 점수를 `state.json`에 저장해 재실행 후에도 유지합니다.
5. 파일이나 입력 오류는 `try/except`로 처리합니다.
6. 기능 브랜치는 작업을 격리하고, 병합은 검증된 변경을 `main`에 통합합니다.
7. 데이터가 커지면 JSON 전체 처리 대신 인덱스가 있는 SQLite로 옮깁니다.
8. `state.json`은 매일 백업하고 정상 JSON인지 확인한 뒤 복구합니다.
